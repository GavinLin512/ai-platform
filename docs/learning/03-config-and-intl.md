## 概念 1：設定檔是程式碼，要用 schema 驗證

設定檔最麻煩的 bug 是**打錯字但沒人發現**：

```yaml
rules:
  no-hardcoded-strng: false   # 少了一個 i
```

如果驗證時直接忽略不認得的 key，這行設定就會默默失效，使用者還以為規則已經關掉了。所以 `src/core/config.ts` 用 zod 的 `z.strictObject`：**遇到不認得的 key 就當成錯誤**。

這跟上一階段的 `env.ts` 是同一個思路：設定錯誤要在第一時間被發現，而不是等到執行時才出問題。Laravel 對照：`$request->validate()` 搭配嚴格的規則，而不是收到什麼就存什麼。

## 概念 2：錯誤訊息要指出位置

「設定檔有錯」沒什麼用，「第 3 行的 `rules.no-hardcoded-strng` 是不認得的設定」才有用。

做法：`yaml` 套件解析時保留每個節點在原文中的位置（`LineCounter` + `node.range`）。zod 回報的錯誤帶有路徑（例如 `["rules", "no-hardcoded-strng"]`），用這個路徑回頭找 YAML 節點，就能算出行號。

找到行號之後，就能沿用 review 留言的機制：PR 改了 `.l10nrc.yml`，錯誤就留在出錯的那一行。

## 概念 3：設定錯了，要繼續還是停下？

兩種選擇：

- 設定有錯就整個停止 review：最安全，但一個小錯字就讓 bot 完全失效
- **設定有錯就用預設值繼續 review**，同時把錯誤報出來

這裡選第二種：bot 繼續提供價值，錯誤也不會被埋沒。

另一個取捨是讀**哪個版本**的設定檔：這裡讀的是 PR head 的版本，所以修改設定檔的 PR 本身就能看到新設定的效果。代價是 PR 可以順便把規則關掉；對 review bot 來說這可以接受，但如果是安全檢查工具，就應該改讀 base branch 的版本。

## 概念 4：為什麼 `toLocaleDateString()` 不加參數是 bug

不加參數時，它用的是**執行這段程式碼的那台機器的 locale**：

- 在瀏覽器裡：使用者瀏覽器的語言設定
- 在 Next.js 的 server-side rendering 裡：**伺服器**的 locale，通常是 `en-US`

結果是同一個頁面，伺服器渲染出 `11/4/2026`，瀏覽器重新渲染時變成 `2026/11/4`，React 會報 hydration mismatch。解法是一律明確傳入使用者的 locale。

## 概念 5：亞洲各地的格式差很多

這些是 Node 實際輸出的結果：

| locale | 日期 | 數字 1234567.891 | 金額 1234.5 |
|---|---|---|---|
| zh-TW | 2026/11/4 | 1,234,567.891 | $1,234.50（TWD） |
| ja-JP | 2026/11/4 | 1,234,567.891 | ￥1,235（日圓沒有小數） |
| ko-KR | 2026. 11. 4. | 1,234,567.891 | ₩1,235（韓圜沒有小數） |
| th-TH | 4/11/**2569** | 1,234,567.891 | ฿1,234.50 |
| vi-VN | 4/11/2026 | **1.234.567,891** | **1.235 ₫**（符號在後面） |
| en-US | 11/4/2026 | 1,234,567.891 | $1,234.50 |

幾個容易踩到的地方：

- **泰國預設用佛曆**，西元 2026 年是佛曆 2569 年
- **越南**用逗號當小數點、句點當千分位，跟台灣剛好相反
- 日圓、韓圜、越南盾**沒有小數**，`toFixed(2)` 會顯示出不存在的「分」

手寫 `"$" + price.toFixed(2)` 的話，上面這些全部都會錯。`Intl.NumberFormat(locale, { style: "currency", currency })` 會自動處理。

## 概念 6：兩條規則撞在一起的時候

台灣的程式碼很常寫 `NT${price}`。`NT$` 有英文字母，`no-hardcoded-string` 原本會把它當成要翻譯的文字；`intl-format` 也會把它當成手寫的貨幣符號。結果**同一個問題被報兩次**。

解法是讓每個問題只有一條規則負責：`NT$`、`US$` 這類貨幣前綴不算可翻譯的文字，交給 `intl-format` 處理。規則越多，越要注意這種重疊，否則 bot 會變得很吵。

## 概念 7：突變測試找到了測試的漏洞

這一輪的突變測試，有一個突變**沒有被抓到**：把「字串串接只報最外層」的邏輯拿掉，測試竟然還是通過。

原因是測試的例子 `y + "-" + (m + 1)` 太短，內層的子運算式只有一個日期 getter，本來就不會被報告。換成實務上常見的長串寫法 `y + "/" + m + "/" + d` 之後，拿掉那段邏輯，同一行就會被報兩次，測試也就抓到了。

突變測試不只驗證程式，**也會找出測試本身的盲點**。

## 動手練習

1. **Laravel 對照題**：設定檔的 `ignore` 用 glob 比對路徑（`legacy/**`）。在 `test/core/config.test.ts` 加一個測試，確認 `ignore: ["**/*.generated.tsx"]` 會跳過 `src/a/b.generated.tsx`。
2. **新的偵測**：`intl-format` 目前沒有檢查 `new Intl.Collator()`（排序用）。中文的排序方式（筆畫、注音、拼音）也會因 locale 而不同，`["張", "王", "李"].sort()` 的結果對使用者沒有意義。要不要把它加進規則？會有誤報嗎？先想清楚再寫測試。
3. **取捨題**：概念 3 提到設定檔讀的是 PR head 的版本。如果改成讀 base branch 的版本，要改哪裡？修改設定檔的 PR 會發生什麼事？
